# A reflexao descreve UFunction e UProperty. Ela NAO descreve virtual nativa
# comum — e algumas importam. `APrimalStructure::TakeDamage` nao tem `exec`,
# logo nao e UFunction, logo nao aparece na reflexao: um plugin de PvE que
# precisa CANCELAR dano numa estrutura nao tem outro caminho.
#
# Um plugin pede pelo nome (api->EnderecoDaAncora) e desvia com HookFuncao.
#
# ISTO NAO E A TABELA DE OFFSETS QUE DEIXAMOS PARA TRAS, e a diferenca e o
# ponto inteiro:
#   · aquela tinha 555.540 entradas e era BAIXADA de um servico que nao
#     controlamos. Nao publicada para a build nova, nada funcionava.
#   · esta tem meia duzia de linhas, vem junto com a API, e so' e' precisa
#     pelos poucos plugins que desviam virtual nativa. Todo o resto — toda
#     UFunction, todo campo, toda classe — vem da reflexao viva.
#
# Faltar uma ancora e um plugin que nao faz UMA coisa. Nao e um servidor que

# ── o RELOGIO, e por que ele nao pode vir do ProcessEvent ──────────────────
#
# UWorld::Tick roda UMA VEZ POR QUADRO, e so' existe quando ha mundo. E' de la
# que a AsaApi puxa os tiques e os timers dos plugins dela — conferido no fonte
# dela (HooksImpl.cpp: UWorld.Tick e AGameState.DefaultTimer).
#
# A BRZ Api puxava da CONTAGEM DE DESPACHOS do ProcessEvent: um "batimento" a
# cada 256 despachos. Durante o carregamento do mundo a GameThread nao faz outra
# coisa senao ProcessEvent — centenas de milhares de BeginPlay — entao o
# batimento rodava no talo, dentro da propria thread que devia estar carregando
# o mundo. E a lista "por tique" disparava toda vez que o MILISSEGUNDO mudava:
# ate 1000 Hz, contra os ~30 Hz de um quadro.
